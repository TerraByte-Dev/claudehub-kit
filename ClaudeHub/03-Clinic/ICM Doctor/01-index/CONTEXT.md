# 01 — Index  ·  CONTEXT

> **The registry (source of truth).** The catalog of every ICM structure built, repaired, or
> worth remembering. When you need to find a known structure — or prove what exists — you come here.

## Identity
The front desk and the filing cabinet. This room is the **declared source of truth** for the
whole repo: if two rooms disagree about what exists, this one wins. It holds no work in
progress — only the authoritative list of structures and what each one demonstrates.

## What lives here
```
REGISTRY.md   · the catalog: every ICM structure, its role/health, and the pattern it best shows
```

## Inputs
- A structure that just passed the health checklist (from `04-utilities` / `03-building`).
- A real-world structure worth cataloguing as an example to learn from.

## Process
1. **Register on completion.** When a structure is created or repaired to Healthy, add or update
   its row in `REGISTRY.md`.
2. **Annotate the lesson.** Note the one ICM pattern it best demonstrates (so it earns its place
   as a teaching example), and point to where that pattern is explained in `06-resources`.
3. **Keep it honest.** Record the actual health status, including "Needs care" — the registry is a
   mirror, not a trophy case.

## Outputs / Handoff
- A single trustworthy answer to "what ICM structures exist, and which one should I copy?"
  Consumed by `02-planning` (what to model a new build on) and `05-distributable`.

## Conventions
- One row per structure: path · type · zones · pattern-it-demonstrates · health · last-checked.
- This room never holds drafts — design happens in `02`, building in `03`.
