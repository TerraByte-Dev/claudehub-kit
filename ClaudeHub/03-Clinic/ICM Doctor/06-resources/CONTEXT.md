# 06 — Resources  ·  CONTEXT

> **The reference library (cross-cutting).** Stable knowledge the whole repo reaches
> into: the canon's depth, the lexicon, the paper. A shelf, not a stage — you draw from it,
> you rarely change it.

## Identity
The library. The parts of the canon too heavy for the root `CLAUDE.md` live here, kept stable
so the floor plan stays scannable. Every other room cites this one; nothing here is about a
single job. If a fact is true across *all* ICM work, it belongs here.

## What lives here
```
icm-lexicon.md             · role → canonical name → aliases. The alias map.
icm-paper-distillation.md  · faithful, cited summary of ICM (arXiv 2603.16021).
icm-patterns.md            · moves that survived contact — problem → move → tell.
```

## Inputs
- A stable truth about ICM worth writing once and citing everywhere.
- A new alias spotted in the wild — a folder that *means* "Output" but is named "Storage."

## Process
1. **Cite, don't copy.** Other rooms link here; they do not restate it.
2. **Grow the lexicon on contact.** Diagnosing a project and you hit an unknown name? Add the
   alias here so the Doctor recognizes it next time.
3. **Keep references ≤ 200 lines.** Split a swelling reference and route to its parts.

## Outputs / Handoff
- Stable knowledge consumed by every room — especially `04-utilities` (the playbooks lean on
  the lexicon) and the root `CLAUDE.md` (which routes here for depth).

## Conventions
- A shelf, not a stage: edits are deliberate and rare.
- Each reference opens with a one-line note on what it is and who cites it.
- Aliases are facts, not opinions — record what's *observed*, and where it was seen.
