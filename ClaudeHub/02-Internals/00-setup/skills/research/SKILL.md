# /research

The research desk is `{{RESEARCH_PATH}}`. Its method is `{{RESEARCH_PATH}}/METHOD.md`;
follow it. This skill only gets you there from whatever folder the user is in.

1. Read `{{RESEARCH_PATH}}/INDEX.md`. If the question is already answered and still fresh,
   give the bottom line and the link, and stop.
2. Otherwise read `METHOD.md`, pick a depth (or use the one they named: quick, standard, deep),
   say it in one line, and run it. The brief goes in a new dated folder in the research desk,
   not in the folder they're working in.
3. Finish with the bottom line in chat (two to four sentences), the confidence, and the path
   to the brief. If the answer changes how the project they're in works, say so, and change
   that project's files only if they agree.

Platform rules, outreach law (email, SMS, calls) and prices move often: prefer the platform's
or regulator's own page, date what you read, and mark anything you couldn't confirm. Growth
tips with no platform source are folklore; label them. A question about what TerraByte offers
is never researched: it's answered only from what Tate gave in writing (the Hub or a file he
sent), otherwise `[UNKNOWN - ask Tate]`.
